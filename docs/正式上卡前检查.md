# 正式昇腾上卡前准备与执行门槛

本文件是**第二轮准备补齐**（2026-09-08机器时间），不是首次CPU训练报告的替代。首次结果见[实测结果](实测结果.md)，软件栈/910与910B配套说明见[运行与昇腾适配](运行与昇腾适配.md)。本轮不连接服务器、不安装torch_npu/驱动/CANN、不新增长训、不改archive或split；只补环境保护和同权重数值验收。

## 0. 顺序与停止条件

| 阶段 | 允许进入下一步的条件 | 不能据此声称 |
|---|---|---|
| 环境快照/平台保护 | 无fail；warn逐条人工核对910或910B具体产品、架构、driver/CANN/torch_npu官方矩阵并留记录；保护已安装框架 | 硬件已被本代码认证兼容 |
| 相同权重CPU→NPU推理对齐 | checkpoint/样本/预处理/源码身份完全匹配，logits与loss都finite且在事先确定容差内 | 反向、优化器、准确率已对齐 |
| NPU真实短训练/保存重载 | 现有smoke成功：有限loss/梯度、非零梯度、真实参数变化、val/test推理、strict重载误差达标 | 已完成长训/临床质量验收 |
| 扩展 | 先排查上述阶段差异，再单独评估Lightning NPU、AMP、compile、HCCL多卡/性能 | 可以同时开启所有优化 |

跨split重复图片、越界polygon、患者隔离是**正式精度训练**前置；不阻塞这次仅证明算子/工程链路的验证，也不能擅自重切数据掩盖问题。当前Lightning `train.py`仍不支持NPU，首次上卡用eager CLI。

## 1. 只读环境预检

```bash
# 项目根，已进入目标独立Python环境；本机将python替换为.venv/Scripts/python.exe
python -m scripts.preflight --device npu --timeout 30 --output artifacts/npu-preflight.json
```

- **退出0=pass，2=warn（需人工审阅，不是ready），1=fail（停止）**。输出路径必须不存在。
- 支持cpu/cuda/npu，目标是单设备FP32 eager。预检探测设备0；训练/比较时可显式选`npu:0`或其他合法编号，不会自动DDP。
- 记录CPU架构、Python/platform、torch/torchvision/torch_npu/相关依赖版本；用独立进程做框架import和设备发现，默认每个子进程30秒、可设1–120秒；`npu-smi info`也有超时。设备初始化/命令异常都不能静默回退CPU。
- NPU记录`npu-smi`产品信息和已知driver/CANN版本文件，默认`/usr/local/Ascend`，可`--ascend-root`指定；不存在记unknown/warn。不递归扫描系统，不输出所有环境变量，不安装/修改环境、不自动source脚本。
- 缺包、不可用、已知torch2.1↔vision0.16/patch/build tag矛盾、torch_npu基础版本矛盾、NPU使用CUDA torch是fail。
- 其他torch版本不盲称已配对，报告warn。**NPU即使包和设备可用也至少warn**：必须人工核实910 vs910B/Atlas产品、架构、固件驱动/CANN/toolkit/kernels和torch_npu post版本。`compatibility_certified`始终false。预检pass只代表已测CPU基本发现，不是算子全覆盖。
- 子进程尾部输出写入本地JSON便于排错；不读取密钥文件。若本机第三方导入输出敏感路径，请在分享报告前审核脱敏。

## 2. 安装依赖前保护已安装框架

先按[官方安装流程及配套表](https://github.com/Ascend/pytorch/blob/master/COMPATIBILITY.md)在目标独立环境安装已批准、架构匹配的torch/vision/torch_npu；不要执行cu121安装命令。然后：

```bash
python -m scripts.platform_guard create --device npu --output artifacts/platform-before
# 返回1：没有生成constraints，先修环境。返回2：生成了快照但存在warn，先人工核对，不要忽略。
# 确认warn后，约束传递依赖的版本（不执行自动安装）
python -m pip install -c artifacts/platform-before/constraints.txt -r requirements-runtime.txt
python -m pip check
python -m scripts.platform_guard verify artifacts/platform-before/guard.json --output artifacts/platform-after.json
```

create重新在当前Python里预检，避免拿过期/他机报告生成约束。预检和保护工具主体只依赖标准库，不先要求安装runtime/packaging；wheel版本解析采用有限公开格式，未知格式fail要求人工审核而不猜配套。保护torch、torchvision和已安装torch-npu的**完整版本包括+cpu/+cu等本地标签**；生成`constraints.txt`、`guard.json`、`preflight.json`，默认拒绝覆盖。NPU缺失不导出可用约束。verify检测版本变化、缺失、额外安装torch_npu，以及constraints字节hash被改；失败退出1。

**限制**：pip constraints是准确版本约束，不证明同版本二进制来源，也不是wheel的加密锁。必须保留官方wheel/checksum，不用`--upgrade/--force-reinstall/--ignore-installed`绕开保护，不混其他index；pip无法满足约束时应失败，不放宽torch pin求安装成功。verify通过也不能证明CANN配套。NPU上若原runtime固定版本不适配新官方torch，需要另建并验收新基线，不盲目升级旧栈。本轮只生成/验证约束，未实际运行新的pip安装。

## 3. 同一已有checkpoint：CPU参考→设备对比

本入口只接受已有smoke的`model.pt`，不接受随机新模型或Lightning `.ckpt`。**只加载可信本地权重和参考**；采用`torch.load(weights_only=True,map_location='cpu')`、state tensor检查、实际原模型`strict=True`加载；这不替代不可信文件隔离/大小控制，不能随意加载外部下载的pickle/checkpoint。

以FCN现有checkpoint为例：

```bash
# 先在CPU生成参考（可以在NPU机器同一环境执行--device cpu，减少框架差异）
python -m scripts.compare_devices reference --checkpoint artifacts/fcn-cpu/model.pt \
  --data archive --split val --indices 0 1 --size 64 --device cpu --output artifacts/fcn-reference

# 先本机CPU自检；同权重时零容差应通过
python -m scripts.compare_devices compare --checkpoint artifacts/fcn-cpu/model.pt \
  --reference artifacts/fcn-reference --device cpu --rtol 0 --atol 0 --output artifacts/fcn-cpu-parity

# 获授权上卡、环境快照和软件栈确认后再运行。不能在当前无NPU环境宣称此步已执行。
python -m scripts.compare_devices compare --checkpoint artifacts/fcn-cpu/model.pt \
  --reference artifacts/fcn-reference --device npu:0 --rtol 0.001 --atol 0.0001 --output artifacts/fcn-npu-parity
```

命令中多行`\`是Linux shell写法；PowerShell用一行执行或反引号续行。已有产物位于`artifacts/preparation/`，不要用已存在的output目录重跑。

- 默认 `val indices=[0,1]`，64×64；模型/类别/encoder取自checkpoint，不能CLI偷偷改结构。可用已有DeepLab、U-Net ResNet50、FCN多分类权重同样验收（不是另造小网络）。支持已验收ResNet50与项目原efficientnet-b7配置，后者本轮没额外上卡/数值实测。
- 身份校验含checkpoint SHA256、COCO JSON SHA256、split/index/image ID、原图片SHA256、类别定义、确定性预处理、输入/target张量shape及hash、模型与数据/比较脚本源码hash（统一LF）。**任一不一致直接失败**，不进入allclose掩盖问题。目标端须同一份源码和数据/权重；Windows→Linux绝对路径不同没关系。
- torch/vision/NumPy/Pillow/SMP版本在双方报告中分别记录，不要求版本字串相同，因为NPU插件版本可能不同；但处理后输入/target hash必须相同。升级或修正比较/模型/数据源码后必须重新生成CPU参考。
- CPU参考输出`reference.json`、`numerics.npz`、`summary.json`；NPZ仅保存FP32 logits和标量loss，**不保存原图或mask数组**。数字也是医疗派生数据，只留受控本地，不能随意公开上传。本轮未传输参考或医疗图像。
- 比较校验NPZ SHA256，读取`allow_pickle=False`，检查输出键、shape、dtype/有限性；只保存汇总，不保存目标设备图像/预测图。
- logits与loss分别给max abs、max rel、mean abs、allclose。规则`abs(actual-reference)<=atol+rtol*abs(reference)`；最大相对误差分母用`max(abs(reference),1e-12)`，近零值可造成高相对误差，应结合绝对误差解释。
- 默认`rtol=1e-3, atol=1e-4`只是**FP32首轮排障起点，不是已确认的910误差预算**；上卡前确定容差并保留在report，失败时定位算子/软件版本，不不断放宽容差到通过。CPU自检用0/0。
- 本轮只做eval eager推理loss对齐，无AMP、BN更新、backward或optimizer跨设备对齐。后续训练由既有smoke验收有限性/变化/重载，两项通过仍不自动证明CPU/NPU梯度数值一致。

## 4. 接着运行NPU训练smoke

```bash
python -m scripts.smoke --device npu:0 --model fcn --size 64 --batch-size 2 --steps 2 --output artifacts/fcn-npu-train
# 再按顺序验DeepLab、U-Net；DeepLab batch>=2，U-Net size是32倍数
```

这一步为工程训练从随机权重开始是允许的，但它**不是上一阶段同checkpoint数值对齐的替代**。保存summary、loss、有限gradient/parameter delta、checkpoint重载误差、设备/版本信息。首次不用Lightning，不开启AMP/compile/DDP。全前景预测等现象仍应记录，不能包装为已达医疗精度。

## 5. 第二轮本机实测证据

复用Windows `.venv` Python3.11.15、torch2.1.0+cpu/vision0.16.0+cpu；未装新依赖/新框架。

| 验证 | 结果 |
|---|---|
| CPU preflight | pass，退出0 |
| NPU preflight | 缺torch_npu/设备fail，退出1；型号/CANN unknown明确记录 |
| CPU平台guard create + verify | 完整+cpu版本pin，verify pass；初测发现Windows换行hash问题后修复并回归 |
| 缺NPU创建平台guard | 退出1，**不产生constraints.txt** |
| FCN、DeepLab、U-Net、FCN多类既有checkpoint CPU→CPU | 四组都在rtol=atol=0下通过，logits/loss max abs=max rel=0 |
| 仅一个FCN参考logit扰动+0.25（更新文件hash，确保走数值分支） | logits max abs≈0.249999993、max rel≈0.765926427，allclose=false，退出1；loss仍相等 |
| 换checkpoint为多类FCN | 身份失败，退出1；列出checkpoint/classes/loss/target差异 |
| 换真实样本indices为1,2 | 身份失败，退出1；列出image IDs/hash/input/target差异 |
| 换size=32 | 身份失败，退出1；列出shape/预处理/input/target差异 |

| 回归 | **32 passed**，16条第三方弃用warning；见`artifacts/preparation/pytest.log`（包含第一轮10项） |
| 数据完整性 | 再次核验原673个引用图+COCO JSON SHA256，全部未变 |
| 依赖检查 | uv pip check，81包通过 |

四组参考仅使用已有经过短训练的权重，无新增训练、无隐式预训练下载。CPU结果不证明NPU任何算子已实测。
