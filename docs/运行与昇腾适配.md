## 范围与状态

本轮目标是**新 archive 真实数据上的工程可运行证明**，不是论文复现或医疗准确率验收。保留 FCN-ResNet50、DeepLabV3-ResNet50、SMP U-Net 原网络；不使用替代小网络。短训练默认随机初始化，**不下载预训练权重**。原始 `archive/`、`archive.zip` 和 `现状分析.md` 不修改，不上传图像，不提交 Git，不连接/开通服务器资源。

`现状分析.md` 是旧静态审计快照：其“没有数据”的结论已被新 archive 替代，其“停止实施”是上一阶段要求，不适用于本轮已批准实施。最终实测见 [实测结果.md](实测结果.md)。

## 1. 本机隔离环境（项目根执行）

实测基线：Windows、Python 3.11、torch 2.1.0、torchvision 0.16.0、Lightning 2.1.0、SMP 0.3.3。不要直接安装原 `requirements.txt` 全量依赖；不要使用全局 Python 3.13 恢复 torch 2.1。

```powershell
uv venv --python 3.11 .venv
# CPU验收，无GPU也能完成
uv pip install --python .venv/Scripts/python.exe torch==2.1.0 torchvision==0.16.0 --index-url https://download.pytorch.org/whl/cpu
uv pip install --python .venv/Scripts/python.exe -r requirements-runtime.txt
uv pip check --python .venv/Scripts/python.exe
```

若明确需要本机 NVIDIA 运行，可在**另一个隔离环境**将框架索引替换为 `https://download.pytorch.org/whl/cu121`。该 Windows CUDA wheel 约 2.3 GiB，本轮下载曾超时，实际使用 CPU 验收。驱动显示 CUDA 13.1 是驱动支持上限，不等于应安装 CUDA 13.1 的 torch。

`requirements-runtime.txt` 不写 torch/torchvision 直接依赖，但 Lightning/SMP 有传递依赖，故**必须先安装正确平台框架**；NPU 使用下文 constraints 保护，不可直接套用上面的 cu121 命令。`numpy==1.26.4` 避免老 torch 的 NumPy 2 ABI 问题；`setuptools==75.8.2` 提供 Lightning 2.1 必需的 `pkg_resources`。完整本机包列表在 `artifacts/environment-freeze.txt`，仅作证据，不可拿它给 NPU 安装。

## 2. 数据检查

```powershell
.venv/Scripts/python.exe -m scripts.audit_data --data archive --output artifacts/data-audit.json
```

加载器同时支持 `oral1/<file_name>` 和本次 Kaggle 解压结构 `oral1/oral1/<file_name>`，忽略 JSON 中不可移植的 `/datasets/...` 绝对路径。审计执行全部被引用图片的存在/解码/尺寸检查、类别/annotation 引用检查、polygon 点数/有限性/面积/边界检查、split ID/文件名/文件 SHA256/解码 RGB SHA256 重叠检查。

- 二分类是所有病灶 polygon 并集，不再只取第一 annotation 的最长 polygon。
- 多分类是背景0 + `neoplastic=1 / aphthous=2 / traumatic=3`，输出 one-hot；若不同类别重叠，后面的 annotation 覆盖前面的像素。本次数据是否含混合类别见审计结果。
- 图像 bilinear resize，mask **nearest**，无 mask/max 除零。无标注图像保留全背景，但不能自动解释成医学阴性。
- 只接受成对确定性 Resize/CenterCrop/ToTensor；随机增强明确拒绝，防止图像与 mask 独立随机变换错位。本轮不实现随机增强。
- `category_id` 第三返回值保留兼容：单一类别正常返回，空标注0、混合类别-1。主训练不依赖该值计算像素指标。
- 文件/像素哈希无重叠**不能证明患者级隔离**，也不能排除近重复、不同视角同病灶；不能直接将短跑 Dice 报成医疗质量。

## 3. 原网络真实数据 smoke

```powershell
.venv/Scripts/python.exe -m scripts.smoke --device cpu --model fcn --size 64 --batch-size 2 --steps 3 --output artifacts/fcn-cpu
.venv/Scripts/python.exe -m scripts.smoke --device cpu --model deeplab --size 64 --batch-size 2 --steps 2 --output artifacts/deeplab-cpu
.venv/Scripts/python.exe -m scripts.smoke --device cpu --model unet --encoder resnet50 --size 64 --batch-size 2 --steps 2 --output artifacts/unet-cpu
# 三类前景+背景，用CrossEntropy
.venv/Scripts/python.exe -m scripts.smoke --device cpu --model fcn --classes 3 --steps 2 --output artifacts/fcn-multiclass-cpu
# 同入口支持cuda:0；若不可用会报错，不回退CPU
```

每个命令固定取 train 前2个真实样本反复做少量 SGD 更新，val 前2个做验证，test 前2个做推理。不是全 split 训练/评价。网络包含原 backbone；DeepLab 训练需要 batch>=2 避免 ASPP 全局池化 BatchNorm 的单样本错误；U-Net 尺寸须32倍数。本轮用64而非448仅为链路验收。

输出目录必须不存在，避免覆盖已有权重。产物仅包含 `model.pt`（CPU state_dict + 基本结构元数据）、`summary.json`，**不导出患者图像或预测图**。检查：loss/logits/所有非空梯度有限、梯度范数>0、输入卷积参数真实变化、val/test前向有限、权重写入、新实例 strict load、同一验证输入 logits `assert_close(rtol=1e-5, atol=1e-6)`。SGD无momentum，checkpoint是推理权重而非完整续训状态。loss 不承诺单调下降；BN训练与eval的loss不可混为同一指标。

## 4. 原 Hydra + Lightning 主训练路径

```powershell
.venv/Scripts/python.exe train.py train.device=cpu dataset.resize=64 train.batch_size=2 train.max_epochs=1 train.max_steps=2 train.limit_train_batches=2 train.limit_val_batches=1 train.num_workers=0 train.pretrained=false train.save_path=artifacts/lightning-smoke
```

继续正常训练时去掉短跑限制，按显存设置分辨率/批次/worker，先解决泄漏、标注、患者隔离问题。`train.device=cpu|cuda:0` 是主入口的新权威设备配置；旧 `accelerator/devices` 只为旧测试脚本保留，主入口不再使用。显式设 `train.pretrained=true` 才允许下载 torchvision DEFAULT/SMP imagenet 预训练；医疗权重不是这些通用预训练权重。默认关闭 W&B，本轮远程日志直接拒绝；本地 TensorBoard 可选。

已恢复丢失包导出，删除 FCN 无效 prototype 导入，修复 OneCycleLR 为每个 optimizer step 调用；训练/验证只前向一次，避免重复 BN 更新；像素准确率和 Dice/IoU 用 device-local 张量计算。原网络 auxiliary head 保留 checkpoint 形状兼容，但原项目只训练主输出，aux head 本轮未新增损失。原手工 test/ensemble 指标与全数据ROC/绘图没有全面重构，不把旧 `test.py/testEnsemble.py` 指标作为本次验收证据。

## 5. 昇腾910：只完成入口和依赖准备，未上卡实测

### 已实现

- `src/devices.py` 显式 `cpu / cuda[:id] / npu[:id]`；仅请求 NPU 时显式 import `torch_npu`。
- torch_npu 缺失、设备不可用或编号越界直接报错，**不会静默回退**。
- 同一个 `scripts.smoke` 使用实际三类模型，可做单卡 FP32 eager 前向、反向、SGD、保存重载；无 CUDA 硬编码移动，无 `transfer_to_npu` monkey patch，无 AMP、compile、DDP/HCCL。
- `train.py` 仍是 CPU/CUDA Lightning 主路径。Lightning 2.1 没有原生 NPU accelerator；传 `train.device=npu:0` 明确说明应先用 eager smoke，不伪称 Lightning NPU 已完成。

### NPU 安装顺序（模板，先填写已核实版本）

```bash
# 全部在独立Linux虚拟环境，路径依机器实际情况
source /usr/local/Ascend/ascend-toolkit/set_env.sh
# 从官方取得适合CPU架构/Python ABI、与已核实torch_npu配套的torch与torchvision
# 使用CPU index或官方指定本地wheel，不使用cu121或Windows freeze
python -m pip install /approved-wheels/torch-<matched>.whl /approved-wheels/torchvision-<matched>.whl
python -m pip install /approved-wheels/torch_npu-<matched>.whl
# 用已安装的准确版本生成 constraints，阻止传递依赖替换框架
python -m pip freeze | grep -E '^(torch|torchvision|torch-npu|torch_npu)==' > platform-constraints.txt
python -m pip install -c platform-constraints.txt -r requirements-runtime.txt
python -m pip check
python -c 'import torch, torch_npu; print(torch.__version__, torch_npu.__version__, torch.npu.is_available())'
python -m scripts.smoke --device npu:0 --model fcn --steps 2 --output artifacts/fcn-npu
```

本地 wheel 文件名模板不是可直接复制执行的真实路径；先完成官方配套确认。ARM64 无匹配 wheel 时按官方源码/镜像流程处理，不能任意替代版本。FP32 eager 首要待验收风险：dilated convolution、bilinear interpolate forward/backward、BatchNorm、SMP encoder/decoder 算子与格式转换、NPU优化器/序列化。若某算子报错，记录完整版本和最小复现，不转CPU掩盖问题。先逐模型验收，再研究性能/AMP/图模式/多卡和Lightning集成。
